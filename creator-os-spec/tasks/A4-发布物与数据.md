# A4 · 发布物 + 手动数据回填

## 目标
每个脚本可挂多个「发布物」(视频/图文,链接/上传),并能手动回填数据。

## 前置
- A3 已通过验收

## 概念
- 一个脚本可发多平台 → 多条发布物记录
- 发布物 type: video / image_text;source: link / upload
- 数据是时间序列:同一发布物多次记录,画增长曲线
- collected_by 标明数据来源(本步都是 manual;A5 加 auto)

## 要做的事
1. 建 ORM 模型 `publications`、`publication_metrics`
2. Alembic 迁移并 upgrade
3. Pydantic schema 对应
4. 实现接口:

   | 方法 | 路径 | 说明 |
   |------|------|------|
   | GET | /scripts/{id}/publications | 该脚本发布物 + 每个的最新一条数据 |
   | POST | /scripts/{id}/publications | 新建 {type, source, platform, external_url?, published_at} |
   | POST | /publications/{id}/upload-url | source=upload 时,返回 R2 预签名上传 URL |
   | PATCH | /publications/{id} | 改 {track_status}(active/paused) |
   | DELETE | /publications/{id} | 删除 |
   | GET | /publications/{id}/metrics | 数据时间序列(倒序) |
   | POST | /publications/{id}/metrics | 手动回填 {views,likes,comments,shares,saves,completion_rate},collected_by=manual |

5. 新建 youtube 平台的发布物时,若 external_url 是 YouTube 链接,解析出 videoId 存到 external_id(为 A5 铺路)。解析失败不报错,external_id 留空即可
6. upload-url 接口:storage_key 命名 `publications/{script_id}/{uuid}`,返回预签名 PUT url,让客户端直传 R2

## 验收标准
- 建一个 douyin 链接发布物 → 成功
- 给它手动回填两条数据(不同 recorded_at)→ GET metrics 看到时间序列
- 建一个 youtube 链接发布物 → external_id 被正确解析出来
- GET publications 返回每个发布物 + 最新数据
- track_status 能改成 paused
